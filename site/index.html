01 Setup

One command finds everything.

Init detects your agents and hosts, adopts what you already run, maps identities to remotes and paths, and leaves you a working router.

  • Adopts, doesn't clobberExisting routers, shims and .envrc links are backed up first.
  • Any number of identitiesStart from your config or the two built-in defaults; init keeps asking "Add another identity?" until you say stop.
  • Ends with a checkbarrito doctor tells you what's left.

02 How it works

Resolved at exec. Routed on localhost.

Every agent binary is a shim. The shim decides who you are for this repo, then hands off to one router that knows where that identity's traffic belongs.

01

Resolve

The shim picks the identity at exec: explicit env override, then the git remote owner, then the path glob, then your default. Worktrees anywhere just work.

02

Route

Claude Code on a live Max plan goes straight to Anthropic with its own login. Everything else goes to the gateway on that identity's key.

03

Fall back loudly

When Max is spent or Anthropic is down, traffic moves to GLM 5.3, then DeepSeek V4.1 Flash — and every transition is announced.

03 Features

The right account, every time, without thinking.

Identity by git remote

The remote owner decides who you are, so worktrees anywhere on disk just work — emdash, Conductor, plain tmux. Paths are the backup; an env override is the escape hatch. Results are cached and barrito which explains every match.

Loud fallback

A platform notification, a statusline change, and a line in barrito status on every tier move. Silent otherwise.

Quota aware

Reads Max 5h and 7d utilization from Anthropic's own rate-limit headers and skips the direct route when it's spent.

Any host

Identity resolves in the shim at exec time, not in whatever env the host started with — so emdash, Conductor and tmux worktrees need zero per-host setup. One restart after install picks up the new PATH.

Keys stay out of agent env

The router reads your platform keychain — Keychain on macOS, secret-tool on Linux. Agents get a barrito:<id> handle that's useless anywhere but localhost.

Picker from rules

models sync renders the gateway catalog through your rules into /model rows, per identity. Idempotent; rerun any time.

Graft built in

Pick repos at init. New worktrees of a grafted repo build their per-repo code graph in the background.

04 Harnesses

Claude Code gets the most. Everything gets something.

Support comes in three levels, set by what each harness can accept. The gateway speaks OpenAI and Anthropic, so nothing gets translated.

LevelHarnessesWhat you get
FullClaude CodeMax direct, quota tracking, loud fallback, /barrito slash command, statusline.
GatewayCodex, OpenCode, custom scripts, AI SDK appsThe identity's gateway key via the local proxy. No format translation — the router swaps a handle for a key and reverse-proxies unchanged.
Envcursor-agentThe identity's Cursor key injected into the environment; Cursor's backend can't be proxied.

Bring your own

Any binary in four lines.

Declare the env your tool expects. barrito fills {gateway} and {handle} per identity, then puts a shim on your PATH. Shims are bash with a true exec, so TTY and signals stay native.

~/.config/barrito/config.tomltoml
[harness.mybot]
bin = "mybot"
env = { OPENAI_BASE_URL = "{gateway}/v1", OPENAI_API_KEY = "{handle}" }
terminalsh
$ barrito shim mybot

05 When Max runs out

Cheap first, loudly.

A per-identity tier state machine keeps a spent quota spent across restarts. The triggering error arrives before any stream bytes, so the same request is retried on the fallback chain immediately — you see an answer, not an error. Model output is never mutated.

  • QuotaA direct 429 moves the identity to fallback until the reset timestamp from Anthropic's rate-limit headers; the next request after that probes direct again.
  • OutageA direct 529/5xx or connect error gets one free retry; a second within 60s opens the breaker, which half-opens after 60s and backs off ×2 up to 15m.
  • The statusline is the truthIf Max runs out mid-session the /model label still says Opus — barrito can't change Claude Code's selection. The statusline says what's actually serving you.
  • Pins apply immediatelyOn the next API call, including inside a running turn.

06 Models

The picker writes itself.

Claude Code can't discover gateway models under Max OAuth, so barrito registers them from your rules — rerun any time new models land. Other harnesses need nothing: OpenCode reads the catalog itself, Codex takes any ID via -m, Cursor uses its own models.

~/.config/barrito/config.tomlrules
[models]
require        = ["tool-use"]
include        = ["zai/*", "deepseek/*", "anthropic/*"]
exclude        = ["*-preview"]
max_input_price = 5.00
pin            = ["meta/muse-spark-1.3-contributor"]
  • IdempotentSame catalog in, same files out. Retired models drop out; anything still referencing one is flagged in the dry run and in doctor.
  • Every identityPicker rows and subagent files are written into each Claude config dir, for every identity, with your labels.
terminal — barrito models sync

07 CI

Max in CI. Cheap when it's spent.

Claude Code jobs in GitHub Actions run through genuine Claude Code with your Max OAuth token. When Max runs out mid-run, the job doesn't fail — it falls back to GLM on the repo's gateway key, and the run gets a visible warning annotation plus a step summary.

.github/workflows/ci.ymlyaml
- uses: actions/setup-node@v4
  with: { node-version: 22 }
- run: npx barrito ci --identity ci --gateway-key env:AI_GATEWAY_API_KEY --fallback zai/glm-5.3
  env:
    AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
- run: claude -p "fix the failing test"
  env:
    CLAUDE_CODE_OAUTH_TOKEN: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
- if: always()
  run: npx barrito ci stop
annotationgithub actions
⚠ barrito · ci — Max spent.
   Now GLM 5.3 on API credits until 14:05.

How it works

barrito ci writes shims to $GITHUB_PATH, the router env to $GITHUB_ENV, starts the router detached and waits for /health. ci stop writes status --markdown into the step summary and never fails the job — pair it with if: always(). Without CLAUDE_CODE_OAUTH_TOKEN the job still runs, on the gateway chain only. Compliance is unchanged in CI: Max only ever flows through genuine Claude Code; every other tool stays on the repo's gateway key.

08 Compliant by design

Nothing to hide, so nothing to trace.

barrito routes traffic. It doesn't disguise it. Every request goes to a provider you pay, from the client that provider expects.

  • 01Max OAuth only ever originates from genuine Claude Code → Anthropic direct. The router forwards those requests unchanged except stripping barrito's own headers, so Anthropic sees normal Claude Code traffic.
  • 02Non-Claude-Code tools never touch Max — gateway keys only.
  • 03Fallback = a different provider on your paid gateway key, not another subscription.
won't do

What barrito won't do

  • Pool subscriptions
  • Replay OAuth tokens into other tools
  • Spoof clients
  • Translate formats

FAQ

Questions, answered.

Does it work with emdash or Conductor?

Yes. Shims resolve identity at exec time, so it doesn't matter what env the host launched with. Restart the host once after install so it picks up the new PATH — doctor tells you if you forget.

What happens when Max runs out?

barrito sees the 5h or 7d window is spent and routes Claude Code to GLM 5.3, then DeepSeek V4.1 Flash, on that identity's gateway key. You get a notification, a statusline change and an x-barrito-tier header. When the window resets, it switches back to Max automatically.

Can I force a model?

Yes. barrito pin personal glm-5.3 keeps an identity on a model even after reset, and barrito unpin undoes it. Gateway models also show up as rows in Claude Code's /model picker.

Where does my /model picker come from?

barrito models sync renders the gateway catalog through your rules into picker rows and subagent files, for every identity. Rerun it any time new models land; retired models are flagged in the dry run and in doctor.

Where do my keys live?

In your platform keychain — macOS Keychain or Linux secret-tool — or, in CI and containers, an env: or file: ref. The router reads them; agents only see a barrito:<id> handle. cursor-agent is the one exception, since it only accepts a raw key in its environment.

Do I need Graft?

No. It's optional and per repo. Init ranks your repos by tracked LOC and you pick which ones get a code graph; barrito graft add adds more later.

Linux?

Yes. Same router, same CLI: a systemd --user unit for the service, secret-tool for secrets, XDG paths for config and state, notify-send when a display exists.

Does it work in GitHub Actions or Docker?

Yes. barrito ci covers GitHub Actions end to end, and barrito serve --detach covers containers. Secrets come from env: or file: refs, so no keyring is needed.
