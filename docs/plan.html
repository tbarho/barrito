Launch plan · v1.0 · 2026-10-01

barrito

One local router and CLI that picks the right identity for every coding agent, by repo. Claude Code uses that identity's Max login direct to Anthropic. When Max runs out it drops to cheap models on that identity's Vercel AI Gateway key, and it tells you. Every other harness gets the identity's gateway key through a local proxy.

Repo~/Code/barrito
Installnpx · brew · yarn
RuntimeNode ≥ 22.18 · TypeScript
Replacesclaude-router + 4 shims + .envrc links

One release. Everything below ships together. Task order inside the release is sequencing, not phases.

Scope

What ships, what doesn't

In

  • Identities (work, personal, any number), each with its own Claude config dir, gateway key, Cursor key and fallback chain.
  • Identity resolution: env override → git remote owner → path glob → default. Resolved at exec time in a shim, so it works in emdash, Conductor, tmux and plain terminals.
  • Router on 127.0.0.1:4141: direct Max passthrough, quota tracking, loud cheap-first fallback, gateway proxy for other harnesses.
  • Harness support at three levels: Full (Claude Code), Gateway (Codex, OpenCode, custom, AI SDK apps), Env (cursor-agent). Custom harnesses come from config.
  • Wizard barrito init, plus status, which, doctor, pin, models, graft, shim, logs, exec, env, uninstall.
  • Rule-based Claude Code model registration: barrito models sync renders the gateway catalog (filtered by your rules) into modelPicker and the subagent files for every identity. Rerunnable; replaces the hand-kept claude-settings.json and global/agents/.
  • /barrito slash command installed into each Claude config dir (status, pin, unpin from inside a session).
  • Loud signals: platform notification on every tier change (macOS notification, Linux notify-send, GitHub annotation in CI), a statusline segment, an x-barrito-tier response header, and the log.
  • Linux, same router and CLI: systemd --user service unit, secret-tool keychain, XDG paths, notify-send.
  • CI: barrito ci for GitHub Actions (shims → $GITHUB_PATH, router env → $GITHUB_ENV, tier changes + API spend → the step summary) and serve --detach for containers, with env:/file: secrets where there's no keyring.
  • Graft wiring per chosen repo, with a background graph build in fresh worktrees.
  • Migration off the current setup, backed up first.
  • npm package + Homebrew tap + launchd/systemd service.
  • Landing page (index.html of this site), README, --help for every command.

Out, deliberately

  • Format translation (OpenAI ↔ Anthropic). The gateway speaks both.
  • Max for anything other than genuine Claude Code. That's the compliance line.
  • Subscription pooling and multi-account round-robin.
  • Free-tier OAuth providers (Kiro, iFlow, Qwen). Same token-replay pattern, plus unvetted data handling.
  • Proxy-side RTK or caveman rewriting. Those stay at the hook and skill layer.
  • Fallback chains for Gateway-level harnesses. They choose their own model, there's no Max to run out, and the gateway already falls back between providers.
  • Dashboard UI. status, the statusline and logs cover it.
  • Changes to other transcript tooling beyond reading both transcript roots.

Developer experience

CLI spec

A create-next-app-style wizard for setup, then small idempotent commands. Every command has --json where output is tabular, and --yes/flags for non-interactive use. Re-running init edits the existing config; it never duplicates.

In-session control

/model is the steering wheel

Switching inline stays exactly as today. Explicit gateway picker IDs (claude-code/*) bypass the tier state machine; built-in rows (Opus, Sonnet, Fable) are "Max, falling back loudly when spent".

WantHowScope
Switch model now/model → any gateway rowThis session
Max, cheap fallback when spentBuilt-in rowsThis session
Keep every session cheap ("spent for the week")barrito pin personal glm-5.3 or /barrito pin glm-5.3Every session of that identity
Never fall back, show the quota errorbarrito pin work maxEvery session of that identity
  • When Max runs out mid-session, the next API call (not the next turn) goes to the chain. The /model label still says Opus because barrito can't change Claude Code's selection. The statusline is the source of truth.
  • While spent, the options stay inline: keep GLM, /model → Opus 5 (gateway) (Claude on credits), or any other row.
  • Pins and /barrito apply on the next API call, including inside a running turn.

Models

Register gateway models in one command

Claude Code can't discover gateway models under Max OAuth (discovery needs a static ANTHROPIC_AUTH_TOKEN), so the picker must be written. barrito models sync owns that list for every identity. Other harnesses need nothing: OpenCode reads the catalog itself, Codex takes any ID via -m, Cursor uses its own models.

  1. Source: gateway catalog GET /v1/models with the identity key, cached daily.
  2. Filter: require → include → exclude → max_input_price, then pin entries added back.
  3. Render: modelPicker rows (claude-code/ prefix, catalog label, price in the description, grouped by provider) plus generated subagent files (astra, glm, deepseek) into every Claude config dir. Labels set by hand in config win.
  4. Idempotent: same catalog in, same files out. Retired models are removed; a fallback chain or subagent that references one shows ✗ in the dry run and in doctor.
  5. Never writes by itself: doctor and status nudge when new models match your rules. Running sessions keep their picker until restart.

--all works too, but expect 100+ picker rows. Rules give "everything new from providers I care about" without the clutter.

Identity

Who is this repo?

  1. BARRITO_IDENTITY in the environment wins. This is the escape hatch.
  2. Git remote owner. git -C $PWD remote get-url origin, normalized to host/owner/repo and matched against each identity's match.remotes globs. This is what makes emdash and Conductor worktrees in arbitrary directories just work.
  3. Path glob against match.paths, for repos without a remote or for non-repo directories.
  4. Default identity from config.

Results are cached per git toplevel in ~/.local/state/barrito/which.json (key: toplevel + remote URL), so a shim adds one git call on a cold cache and zero on a warm one. The which command prints the matching rule so a wrong match is easy to debug.

Shim (generated, bash, true exec so TTY and signals stay native):

#!/usr/bin/env bash

env finds the real binary as the first match on PATH outside the shim dir, and prints an actionable error if it's missing.

Router

Request handling

Evolves the hand-rolled router it replaces: node:http + fetch, zero runtime deps, streaming passthrough, aborting upstream on client close, logs carry no headers or bodies.

RequestRoute
Bare Claude model (claude-*, anthropic/claude-*, [1m]), identity tier = maxDirect api.anthropic.com. Body model normalized. Strip x-barrito-* and x-ai-gateway-api-key. Everything else unchanged.
Same, identity tier = fallback or pinned to a modelGateway /claude-code; model rewritten to the active chain entry; authorization (Max OAuth) stripped; identity key added.
Explicit gateway picker ID (claude-code/*), *-fast, GET /v1/modelsGateway, unchanged from today. Explicit choices bypass the state machine.
/gateway/* with Bearer barrito:<id>Reverse proxy to https://ai-gateway.vercel.sh/* with the identity key. Any format.
GET /status, GET /healthLocal JSON for the CLI and statusline.
Missing or unknown identity400, Anthropic-shaped error: barrito: no identity for this request — run barrito doctor.

The Vercel key is read from Keychain by the router (cached in memory, re-read on 401). Agents only ever hold a handle. Cursor is the one documented exception.

Fallback

Cheap first, loudly

A per-identity state machine, persisted to ~/.local/state/barrito/tiers.json so restarts don't forget a spent quota.

StateEnter whenLeave when
maxDefault; reset reached; direct success after cooldownA trigger below
fallback(quota)Direct 429 with the unified status rejected, or the utilization headers say spentReset timestamp passes → next request probes direct
fallback(outage)Direct 529/5xx/connect error, twice within 60sHalf-open after 60s: next request tries direct; success → max, failure → back off ×2 (max 15m)
pinnedbarrito pinbarrito unpin
  • No failed turns. The 429 or 5xx that triggers a transition arrives before any stream bytes, so the same request is retried on the chain immediately. The user sees an answer, not an error.
  • Chain walk. If entry n fails (429/5xx), try n+1. When everything fails, return an Anthropic-shaped error listing each hop and its status.
  • Loud on every transition. One notification (osascript display notification; terminal-notifier if present), a log line, a statusline change, and the response header. No repeats until the state changes again.
  • Never mutate model output. No injected text in streams, so context stays clean.
  • Spend tracking. Sum usage from response usage blocks on gateway hops × gateway list price (catalog fetched daily) → API TODAY. Shown as an estimate; Vercel's dashboard is the source of truth.

Statusline: init sets each Claude config's statusLine to barrito statusline. If a statusline already exists, it's wrapped (barrito statusline --append '<existing cmd>'). The command reads the cwd from Claude Code's stdin JSON → identity → /status, with a 50ms timeout and silent degrade.

Graft

Per-repo code graph, opt-in

  • barrito graft scans graft.roots for git repos, ranks by tracked LOC (git ls-files + line count, cached), and shows a checklist. Choices land in graft.repos.
  • Wiring uses the proven minimal flags: graft init --yes --no-global --no-statusline --no-agents --no-build, then graft build. Installs @nanonets/graft if missing (with a prompt).
  • Worktrees, any host: when a shim launches in a worktree of a grafted repo with no graft/, barrito env spawns a detached graft build and returns immediately. No per-host setup scripts.
  • Summaries are off by default and toggled per repo. When on, Graft's provider points at {gateway}/v1 with the repo's identity handle, so each repo bills its own identity's gateway.
  • The wizard warns that graft init writes tracked files (.claude/, .mcp.json, AGENTS.md). Committing them stays the user's call per repo.
  • Other transcript tooling is unaffected, except that its Claude adapter must scan both ~/.claude/projects and ~/.claude-personal/projects: a one-line change in your tooling repo, part of this release.

Tests

What proves it

  • Router unit (mock upstreams on node:http; upstream URLs overridable as today): route table, header stripping per path, model normalization, abort propagation, streaming integrity.
  • State machine: quota 429 → fallback with the same request retried → reset → direct; outage breaker open/half-open/backoff; chain walk; all-fail error shape; pin and unpin; persistence across restart.
  • Identity: table tests for env, remote (ssh/https/enterprise hosts), path, default, cache invalidation on remote change.
  • Shim e2e: env -i PATH=… HOME=… launch from a fake emdash worktree resolves the right identity for each harness, and the real binary gets the expected env (stub binaries print their env).
  • Models sync: fixture catalog → rules → snapshot of modelPicker + agent files; second run = no diff; retired model flagged in chain/subagents; hand labels preserved.
  • Gateway proxy: handle swap, unknown handle → 401, OpenAI and Anthropic paths both pass through byte-for-byte.
  • init: --dry-run snapshot against a fixture HOME with today's setup; idempotent second run = no diff; uninstall --restore round-trip.
  • Manual acceptance: emdash api worktree → work Max; dotfiles worktree → personal Max; Conductor side-project workspace → personal; forced quota (mock) → notification + statusline + GLM answer; Codex and OpenCode in an acme repo bill the acme gateway team (verify in the Vercel dashboard).

  • Every repo under ~/Code/{acme,you} and every emdash/Conductor worktree resolves to the right identity for claude, codex, opencode and cursor-agent.
  • Max quota exhaustion never errors a turn: it falls to GLM 5.3 with a notification and statusline change, and returns to Max after reset with a notification.
  • Both identities' /model pickers are generated by barrito models sync; rerun is a no-op; doctor flags new and retired models.
  • No Vercel key in any agent's environment (Cursor key is the documented exception).
  • Max OAuth never leaves the genuine Claude Code → Anthropic path. Verified by test: the gateway path strips authorization, the direct path accepts only Full-level traffic.
  • Linux and CI jobs green: the ubuntu-latest matrix job and the node:22-slim container job (env:/file: secrets, serve --detach) both pass.
  • A CI run that hits a mocked 429 falls back to GLM instead of failing the job, and writes the warning annotation and the step summary.
  • Old router, shims and symlinks removed; the dotfiles PR is merged; transcript tooling reads both roots.
  • barrito doctor all ✓; test suite green; landing page live.
